The async module contains small control-flow primitives. Time values are always milliseconds.

## Start here: work that finishes later

JavaScript represents a future result with a `Promise`. `await` pauses the current `async` function
until that promise succeeds or fails. It does not freeze the whole browser or server.

```ts
import { sleep } from "@sousaivan/kern/async"

async function greetLater(): Promise<void> {
  console.log("Waiting")
  await sleep(500) // 500 milliseconds is half a second
  console.log("Hello")
}

await greetLater()

await sleep(-1)
// RangeError: Delay must be a non-negative finite number
```

A callback is a function passed to another function. `retry`, `once`, `debounce`, and `throttle`
call the callback according to the rules described below.

The runnable console prints the successful wait first, then shows the invalid negative-delay error.

## At a glance

| Helper | What it does |
| --- | --- |
| `sleep` | Waits for a delay, optionally cancellable. |
| `retry` | Repeats a failing operation under explicit rules. |
| `once` | Runs a function once and replays its result or error. |
| `debounce` | Waits until calls stop, then runs the latest call. |
| `throttle` | Runs immediately, then at most once per interval. |

## Wait with `sleep`

Signature: `sleep(milliseconds, options?): Promise<void>`.

```ts
import { sleep } from "@sousaivan/kern/async"

await sleep(250)
console.log("250 ms have passed")

await sleep(-1)
// RangeError: Delay must be a non-negative finite number
```

The signature is `sleep(milliseconds, { signal? })`. The delay must be a non-negative finite
number. Negative values, `NaN`, and infinities throw `RangeError` before a timer starts.

Use an `AbortSignal` when the caller may cancel the work:

```ts
import { sleep } from "@sousaivan/kern/async"

const controller = new AbortController()
const waiting = sleep(10_000, { signal: controller.signal })

controller.abort(new Error("Request closed"))

try {
  await waiting
} catch (error) {
  console.log(error)
}
```

If the signal is already aborted, or aborts during the wait, the promise rejects with
`signal.reason`. When no reason exists it uses a native `AbortError` DOM exception.

`AbortOptions` is the shared type used by `sleep`, `debounce`, and `throttle`, and is included in
`RetryOptions`:

```ts
import type { AbortOptions } from "@sousaivan/kern/async"

const options: AbortOptions = { signal: new AbortController().signal }
```

## Retry an operation

Signature: `retry(operation, options?): Promise<T>`.

```ts
import { retry } from "@sousaivan/kern/async"

const response = await retry(
  async (attempt) => {
    const response = await fetch("https://example.com/api")
    if (!response.ok) throw new Error(`Attempt ${attempt} failed`)
    return response.json()
  },
  { attempts: 4, delay: 250 },
)

console.log(response)
```

`retry(operation, options)` passes the one-based attempt number to `operation` and returns its first
successful result.

| Option | Type | Default | Meaning |
| --- | --- | --- | --- |
| `attempts` | positive safe integer | `3` | Total calls, including the initial call. |
| `delay` | number or `(attempt, error) => number` | `0` | Wait between failed calls. |
| `shouldRetry` | `(error, attempt) => boolean` | Retry | Return `false` to stop and rethrow. |
| `signal` | `AbortSignal` | None | Cancel before an attempt or during a delay. |

```ts
import { retry } from "@sousaivan/kern/async"

const value = await retry(
  (attempt) => {
    if (attempt < 3) throw new TypeError("Temporary example")
    return "ready"
  },
  {
    attempts: 5,
    delay: (attempt) => attempt * 100,
    shouldRetry: (error) => error instanceof TypeError,
  },
)

console.log(value)

await retry(() => {
  throw new Error("Service is still unavailable")
}, { attempts: 2 })
// Error: Service is still unavailable
```

The final operation error is rethrown unchanged. Invalid `attempts` or delay values throw
`RangeError`. Exceptions from `delay` or `shouldRetry` also pass through. Kern does not assume which
errors are safe to retry; use `shouldRetry` for application policy and avoid retrying non-idempotent
work unless the operation supports it.

`RetryOptions` is useful when an application shares one retry policy:

```ts
import { type RetryOptions, retry } from "@sousaivan/kern/async"

const networkRetry: RetryOptions = {
  attempts: 3,
  delay: (attempt) => attempt * 200,
  shouldRetry: (error) => error instanceof TypeError,
}

await retry(() => fetch("https://example.com/health"), networkRetry)
```

## Run a function once

Signature: `once(callback): callbackWrapper`.

```ts
import { once } from "@sousaivan/kern/async"

let generated = 0
const getRequestId = once(() => `request-${++generated}`)

console.log(getRequestId()) // "request-1"
console.log(getRequestId()) // "request-1"

const failOnce = once(() => {
  throw new Error("Configuration is missing")
})

try {
  failOnce()
} catch (error) {
  console.log("First error:", error)
}
try {
  failOnce()
} catch (error) {
  console.log("Same cached error:", error)
}
```

`once(callback)` remembers the first returned value and never calls the callback again. If the
first call throws, it remembers and rethrows the same error on every later call. Arguments from
later calls are ignored because there is no later callback execution.

This works for synchronous return values. If the callback returns a promise, the promise itself is
cached, so all callers share the same pending/fulfilled/rejected promise. Recursive invocation
before the first call completes throws `Error`.

```ts
import { once } from "@sousaivan/kern/async"

const loadConfiguration = once(async () => {
  const response = await fetch("/configuration.json")
  return response.json()
})

const [left, right] = await Promise.all([loadConfiguration(), loadConfiguration()])
console.log(left === right) // true: both calls received the same resolved object
```

## Debounce calls

Signature: `debounce(callback, wait, options?): ScheduledFunction`.

Debouncing is useful for search fields, autosave, and resize work where only the latest call after
a quiet period matters.

```ts
import { debounce } from "@sousaivan/kern/async"

const saved: string[] = []
const saveSearch = debounce((query: string) => saved.push(query), 300)

saveSearch("ker")
saveSearch("kern")

const result = saveSearch.flush()
console.log(saved, result)

debounce(() => undefined, -1)
// RangeError: Delay must be a non-negative finite number
```

Each call replaces the pending arguments and restarts the timer. The callback normally runs once
`wait` milliseconds have passed without another call.

## Throttle calls

Signature: `throttle(callback, wait, options?): ScheduledFunction`.

Throttling is useful for scroll, pointer, and progress events where the first update should be
immediate but later updates should be limited.

```ts
import { throttle } from "@sousaivan/kern/async"

const positions: number[] = []
const trackScroll = throttle((position: number) => positions.push(position), 100)

trackScroll(10) // immediate
trackScroll(20) // retained as the trailing call
trackScroll(30) // replaces the trailing arguments

trackScroll.flush()
console.log(positions) // [10, 30]

throttle(() => undefined, Number.NaN)
// RangeError: Delay must be a non-negative finite number
```

`throttle` invokes immediately when no interval is active. During the interval it retains at most
one trailing call, using the latest arguments.

## Scheduled function controls

Both `debounce` and `throttle` return a `ScheduledFunction`:

| Member | Behavior |
| --- | --- |
| Calling it | Schedules work and returns `void`. |
| `.cancel()` | Clears pending work and returns `void`. |
| `.flush()` | Runs pending work synchronously and returns its result, or `undefined`. |

They accept `{ signal?: AbortSignal }`. Aborting cancels pending work and makes later wrapper calls
no-ops. Calling `.cancel()` only cancels the current pending work; you can schedule the wrapper
again unless its signal is aborted.

The `wait` value must be a non-negative finite number or construction throws `RangeError`. Callback
exceptions thrown by `.flush()` or timer execution are not swallowed.

You can name the wrapper type when passing a scheduled function between modules:

```ts
import { debounce, type ScheduledFunction } from "@sousaivan/kern/async"

const save: ScheduledFunction<[value: string], void> = debounce(
  (value) => console.log(value),
  250,
)

save("draft")
save.cancel()
```

## Common beginner mistakes

- Delays use milliseconds: `1000` is about one second, not 1,000 seconds.
- Timers are minimum delays, not exact schedules. Busy JavaScript can make a callback run later.
- `retry()` cannot know whether repeating an operation is safe. Repeating a payment or create
  request can duplicate work unless the external operation is idempotent.
- `once()` caches a rejected promise too. It does not automatically try again after failure.
- Calling a debounced or throttled wrapper returns `void`; use `.flush()` only when you need to run
  pending work immediately and receive its result.
- Losing the returned scheduled wrapper also loses access to `.cancel()` and `.flush()`.

## Advanced usage

### Exponential retry delay with cancellation

The delay callback receives the failed one-based attempt number and the thrown value. Combine it
with `AbortController` to stop both future attempts and a pending delay:

```ts
import { retry } from "@sousaivan/kern/async"

const controller = new AbortController()

const request = retry(
  async (attempt) => {
    const response = await fetch("https://example.com/data", {
      signal: controller.signal,
    })
    if (!response.ok) throw new Error(`Attempt ${attempt} failed`)
    return response.json()
  },
  {
    attempts: 5,
    delay: (attempt) => 100 * 2 ** (attempt - 1),
    shouldRetry: (error) => error instanceof Error,
    signal: controller.signal,
  },
)

// Call controller.abort() when the page/request no longer needs the result.
await request
```

Kern deliberately does not add random jitter, HTTP status policy, logging, or a maximum elapsed
time. Those are application decisions. The retry callback may return either a direct value or a
promise-like value.

### Scheduled wrapper lifecycle

Aborting a signal permanently disables that debounced or throttled wrapper. Calling `.cancel()`
only clears its current pending work, so later calls may schedule again. `.flush()` runs pending work
synchronously and lets callback exceptions pass through.
